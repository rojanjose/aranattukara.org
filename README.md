# aranattukara.org — website (first draft)

A bilingual (English / Malayalam) Jekyll site for Aranattukara, Thrissur, published at
[aranattukara.org](https://aranattukara.org) by GitHub Pages from the `main` branch. Custom
layouts, no theme, only GitHub-Pages-allowed plugins — publish by pushing to `main`.
The planning documents (website plan, technical spec, content checklist) are kept outside this repo.
 **This is the first draft**: the text is written from
Joy Chiramel's book and other sources in our own words, and pictures marked **“Photo to come”**
are illustrated placeholders until real photographs arrive. A yellow banner says so on every
page until you set `sample_content: false` in `_config.yml`.

## Preview locally

```sh
bundle exec jekyll serve --livereload --port 4175
# English:   http://localhost:4175/en/
# Malayalam: http://localhost:4175/ml/
```

First time on a new machine: `bundle install` (gems go to `vendor/bundle`).

> **Local vs GitHub:** this Mac has Ruby 4.0, which can only run the older `github-pages`
> gem (v223 → Jekyll 3.9.0). GitHub builds with v232 (Jekyll 3.10.0, Ruby 3.3). The template
> uses nothing that differs between them. `tools/ruby4-compat.rb` (loaded from the Gemfile)
> patches back a Ruby method that the old Liquid needs; GitHub never uses it. For an exact
> match, install Ruby 3.3 (`brew install ruby@3.3`), put it first on PATH, delete
> `Gemfile.lock`, and `bundle install` again.

## How the two languages work

- Each page has an English file and a Malayalam file **with the same file name**:
  `_places/en/st-thomas-church.md` ↔ `_places/ml/st-thomas-church.md`.
  Use English, lowercase, hyphenated file names in both folders, so URLs stay readable when shared.
- The language comes from the folder automatically. The **EN | മല** switch links to the
  other version, or greys out with "coming soon" if it doesn't exist yet. `tharakans-school`
  is English-only on purpose, to show this.
- Interface text (buttons, labels) lives in `_data/i18n.yml`. Malayalam strings are drafts —
  have a native speaker review them.
- `ruby tools/check-pairs.rb` lists missing translations and pairs whose dates, coordinates,
  photos or tags disagree.

## Writing content

Copy a sample file and change it. Front matter for each type is in technical-spec §7; the
samples show every field in use. Highlights:

| Type | Folder | Key fields |
|---|---|---|
| History chapter | `_stories/` | `kind: chapter`, `series`, `order`, `hero`, `sources`, `places`, `people` |
| Memory | `_stories/` | `kind: memory`, `quote` (shown on the home page), `author` |
| Place | `_places/` | `type`, `coords`, `timings`, `festivals`, `walk_stop`, `photos` |
| Person | `_people/` | `years`, `role`, `photo`, `consent` |
| Event | `_events/` | `date`, `end_date`, `time`, `place` (a place slug), `poster` |
| Business | `_data/businesses.yml` | one record with `en`/`ml` values |

`places:` and `people:` lists (slugs) link pages together; the "Related" strip and the
reverse links on place and person pages are built from them.

Past events disappear from "Coming up" by themselves (the browser checks the date), so there
is no need to rebuild when an event ends.

## Pictures

- `tools/build-images.py` turns the source pictures (kept outside this repo, in `../specs/pictures/`) into site images
  and writes `_data/credits.yml` (author, licence, source, processing notes). Every real picture
  shows its credit; the full list is on the **Picture credits** page (`/en/credits/`).
- `ruby tools/placeholders.rb` makes a “Photo to come” illustration for every picture name the
  content uses that has no photo yet, and writes the shopping list `../specs/pictures/NEEDED.md`.
- When a photo arrives: run `tools/optimize-images.sh <file> <name>` (or add it to
  `build-images.py` with its credit), then `ruby tools/placeholders.rb` — the placeholder is
  removed automatically.

```sh
tools/optimize-images.sh ~/Drive/Aranattukara/originals/church-1965.jpg st-thomas-1965
```

writes four web sizes to `assets/img/` (needs `brew install webp`). Refer to the photo by its
base name — `hero: st-thomas-1965`. When a real photo exists, delete the matching placeholder
`.svg` (for example `assets/img/st-thomas-church.svg`); the template prefers an `.svg` when one exists.
Keep originals out of the repo.

## Publish

This folder is the repo root. GitHub Pages deploys from branch `main`, folder `/ (root)`,
custom domain `aranattukara.org` (`CNAME`). DNS is on Cloudflare: A/AAAA records for `@`
pointing to GitHub's Pages addresses and a `www` CNAME to `rojanjose.github.io`, all set to
**DNS only** (grey cloud), with Enforce HTTPS ticked in Settings → Pages.

Publishing is `git push`; GitHub rebuilds in about a minute (Actions → "pages build and deployment").
